# vee-validate recipes for forms that outgrow a dialog

Companion to `vue-forms-validation/SKILL.md`. Assumes `vee-validate` 4.15
with `@vee-validate/zod` or `@vee-validate/valibot`. Pin the schema library
to the adapter's `peerDependencies` range; check with
`npm info @vee-validate/zod peerDependencies` before upgrading either side.

## Choosing zod or valibot

| Concern | zod | valibot |
| --- | --- | --- |
| Bundle | Whole library in one import (~50 KB min) | Tree-shaken functions, usually under 10 KB for a form |
| Adapter peer range (4.15.1) | `zod ^3.24` (zod 4 via its `zod/v3` entry, or wait for an adapter release that lists `^4`) | `valibot ^1.0` |
| Async refinements | `superRefine(async)` | `pipeAsync` / `checkAsync` with `safeParseAsync` |
| Cross-field | `.refine` on the object with `path` | `forward(check(...), ['confirm'])` |
| Team familiarity | Higher | Lower |

Either way, keep the schema in a `schemas/` module beside the API types so
the server team can review it, and export the inferred type for the API
call.

## Conditional sections

```ts
const schema = z.discriminatedUnion('type', [
  z.object({ type: z.literal('person'), name: z.string().min(1), idNo: z.string().length(18) }),
  z.object({ type: z.literal('company'), name: z.string().min(1), taxNo: z.string().min(15) }),
])
```

In the template, `v-if="values.type === 'company'"` on the section. When a
section disappears, call `setFieldValue('taxNo', undefined)` or use
`keepValuesOnUnmount: false` on the field so stale values do not fail the
other branch.

## Multi-step wizard

- One `useForm` with the full schema and `initialValues` in the wizard
  page. Render steps with `v-show`, not `v-if`: a step component that
  unmounts loses its field registration and its errors. If steps must be
  separate components, give each one `useFormContext()` and keep
  `keepValuesOnUnmount: true` on their fields.
- Advance only after `validate()` on that step's fields passes; use the
  returned `errors` object filtered by the step's field names rather than a
  separate per-step schema, so the rules stay in one place.
- Store `step` in the route query so refresh keeps the position; never put
  the draft in the URL.
- Persist the draft to `sessionStorage` on `watch(values)` debounced 500 ms
  if the wizard exceeds two steps; clear it on success.
- The final submit validates everything again; a step the user skipped by
  editing the URL must not get through.

## Field arrays with nested validation

```ts
const { fields, push, remove, move } = useFieldArray<Line>('lines')
push({ sku: '', qty: 1 })                              // key is generated by vee-validate
```

- Rules on items go in the schema (`z.array(lineSchema).min(1)`); rules on
  the whole array (`max 50 lines`, `no duplicate sku`) use `.refine` on the
  array with a message, and show it next to the "add" button.
- Row-level errors are keyed `lines[2].sku`; read them with
  `errors[`lines[${i}].sku`]`.
- `move` keeps errors attached to the right row; manual splice on the model
  does not.

## Server errors and optimistic reset

```ts
const onSubmit = handleSubmit(async (values, { resetForm, setErrors }) => {
  try {
    const saved = await api.save(values)
    resetForm({ values: saved })                       // dirty=false, new baseline
  } catch (e) {
    if (isValidationError(e)) setErrors(e.fields)      // { email: 'taken' }
    else throw e                                        // let the api layer toast it
  }
})
```

`setErrors` marks fields as invalid until the next validation on them; the
error clears when the user edits the field because validation reruns.

## Unsaved-changes guard

```ts
onBeforeRouteLeave(() => !meta.value.dirty || window.confirm(t('form.leaveUnsaved')))
window.addEventListener('beforeunload', (e) => { if (meta.value.dirty) e.preventDefault() })
```

Remove the `beforeunload` listener on unmount; a leaked listener blocks
navigation on unrelated pages.

## Testing the schema

```ts
describe('registerSchema', () => {
  it.each([
    [{ email: 'a@b.co', password: 'longenough', confirm: 'longenough' }, true],
    [{ email: 'nope', password: 'longenough', confirm: 'longenough' }, false],
    [{ email: 'a@b.co', password: 'longenough', confirm: 'different' }, false],
  ])('%o → %s', (input, ok) => expect(schema.safeParse(input).success).toBe(ok))
})
```

Test the schema, not the component, for rule coverage; test the component
only for behaviour (first error focused, submit disabled while pending).

## Element Plus inputs inside a vee-validate form

Element Plus inputs work with `defineField` bindings, but `el-form-item`
needs `:error="errors.email"` to show the message and `:validate-status`
for styling, because `el-form` is not driving validation:

```vue
<el-form-item :label="t('f.email')" :error="errors.email">
  <el-input v-model="email" v-bind="emailAttrs" name="email" />
</el-form-item>
```

Do not also pass `rules` to `el-form`; that is the two-sources-of-truth
bug.
